## 🔦 Project Spotlight — `darkstore-allocation-engine`

**The problem:** in quick-commerce, an order has to be routed to the right dark store within seconds — and two customers can't be allowed to claim the same unit of inventory at the same time.

**What I built:** an allocation engine that finds the nearest eligible dark store using MongoDB's `2dsphere` geospatial indexing, then reserves the inventory atomically so concurrent orders can never double-claim stock.

**Why it mattered to get right:**
- Geospatial querying for real store-proximity ranking, not a flat distance approximation
- Atomic, concurrency-safe inventory reservation — the exact class of bug that causes overselling in production
- Built as a system that assumes concurrent load from day one, not one patched for it later

[**→ View the repo**](https://github.com/Keshavsspppp/darkstore-allocation-engine)
